# Production Checklist

Универсальный чеклист для качественного запуска и работы любого веб-сервиса.
Каждый пункт объясняет ЧТО, ЗАЧЕМ и КАК.

---

## 1. Домен и DNS

**Принцип:** DNS — это «телефонная книга» интернета. Когда пользователь вводит адрес, DNS превращает имя в IP-адрес сервера. Если DNS настроен неправильно — сайт не откроется, даже если сервер работает.

- [ ] **`www.domain.ru` — канонический домен**
  - Зачем: голые домены (`domain.ru`) чаще блокируются DPI-фильтрами российских провайдеров. `www` — это поддомен, он проходит через фильтры свободнее
  - Как: в nginx `server_name www.domain.ru` в основном блоке

- [ ] **Голый домен → 301 редирект на www**
  - Зачем: чтобы пользователи, набравшие `domain.ru`, автоматически попали на `www.domain.ru`. 301 = «перемещён навсегда» — браузер запомнит и в следующий раз пойдёт на www сразу
  - Как: отдельный server-блок в nginx с `return 301 https://www.domain.ru$request_uri`

- [ ] **A-записи для обоих доменов**
  - Зачем: и `domain.ru`, и `www.domain.ru` должны резолвиться в IP сервера. Без A-записи для www — редирект некуда будет отправить
  - Как: в панели DNS регистратора: `domain.ru → A → IP`, `www → A → IP` (или CNAME на domain.ru)

- [ ] **TTL DNS-записей: 300-3600 сек**
  - Зачем: TTL (Time To Live) — как долго DNS-серверы кешируют запись. Малый TTL = быстрее применятся изменения при переезде. Слишком малый = больше DNS-запросов = медленнее
  - Норма: 300с при переезде, 3600с в стабильном состоянии

## 2. SSL/TLS

**Принцип:** SSL/TLS — это шифрование соединения. Без него данные (пароли, формы) передаются открытым текстом. Браузеры помечают HTTP-сайты как «Не защищено», а поисковики понижают их в выдаче.

- [ ] **Сертификат покрывает ОБА домена**
  - Зачем: если сертификат только для `domain.ru`, то `https://www.domain.ru` покажет ошибку SSL — браузер откажется открывать
  - Как проверить: `openssl x509 -in fullchain.pem -noout -text | grep DNS`
  - Как выпустить: `certbot certonly --nginx -d domain.ru -d www.domain.ru`

- [ ] **Автообновление сертификата**
  - Зачем: Let's Encrypt сертификаты живут 90 дней. Забыл обновить — сайт перестаёт открываться с ошибкой «сертификат истёк»
  - Как: `systemctl enable certbot.timer` или cron: `0 3 * * * certbot renew --quiet`

- [ ] **TLS 1.2 + 1.3**
  - Зачем: TLS 1.0 и 1.1 имеют уязвимости, браузеры их не поддерживают. TLS 1.3 — самый быстрый и безопасный
  - Как: `ssl_protocols TLSv1.2 TLSv1.3;` в nginx

- [ ] **HSTS-заголовок**
  - Зачем: говорит браузеру «всегда ходи на этот сайт по HTTPS, даже если пользователь набрал http://». Защищает от атак перехвата при первом подключении
  - Как: `add_header Strict-Transport-Security "max-age=63072000; includeSubDomains" always;`

## 3. Веб-сервер (Nginx)

**Принцип:** Nginx принимает HTTP-запросы от пользователей и решает, что с ними делать — отдать файл, перенаправить, или передать запрос приложению. Правильная структура = безопасность + скорость + SEO.

### Архитектура: 3 server-блока

```
Блок 1 (порт 80):   HTTP → 301 → https://www.domain.ru    Зачем: весь HTTP → HTTPS
Блок 2 (порт 443):  domain.ru → 301 → www.domain.ru        Зачем: голый → www
Блок 3 (порт 443):  www.domain.ru → 200                     Основной сайт
```

- [ ] **Каждый блок на 443 имеет ssl_certificate**
  - Зачем: чтобы принять HTTPS-соединение, nginx должен сначала показать сертификат. Без него — TLS handshake не пройдёт, и nginx не сможет даже отправить редирект

- [ ] **Security headers**
  - `X-Frame-Options: SAMEORIGIN` — запрещает встраивать сайт в iframe на чужих сайтах (защита от clickjacking)
  - `X-Content-Type-Options: nosniff` — запрещает браузеру «угадывать» тип файла (защита от подмены)
  - `Referrer-Policy: strict-origin-when-cross-origin` — контролирует, какую информацию о странице передавать при переходе на другой сайт

- [ ] **Gzip-сжатие**
  - Зачем: уменьшает размер передаваемых данных в 3-5 раз. CSS в 100 КБ → 20 КБ. Сайт загружается быстрее
  - Как: `gzip on;` + список типов файлов (text, css, js, json, svg, woff2)

- [ ] **Кеширование статики**
  - Зачем: файлы JS/CSS/изображения не меняются между деплоями (Vite добавляет хеш в имя). Кеш `1 год` = браузер скачивает файл один раз и больше не запрашивает
  - Как: `location /assets/ { expires 1y; add_header Cache-Control "public, immutable"; }`

## 4. Фронтенд

**Принцип:** всё, что загружается в браузере пользователя, должно быть автономным. Любая зависимость от внешнего сервиса — точка отказа. Если внешний сервис недоступен из России, сайт ломается.

- [ ] **Шрифты self-hosted**
  - Зачем: Google Fonts CDN может быть медленным или недоступным. Self-hosted = шрифт лежит на твоём сервере, загружается гарантированно
  - Как: npm-пакеты `@fontsource/inter`, `@fontsource/montserrat` → import в main.tsx

- [ ] **Никаких внешних CDN**
  - Зачем: Cloudflare заблокирован в РФ (с 2025). jsDelivr, unpkg — могут быть медленными. Любой `<script src="https://cdn...">` — потенциальная проблема
  - Как: все зависимости через npm → бандлер (Vite) включает их в итоговый JS-файл

- [ ] **`.env` на VPS проверен перед билдом**
  - Зачем: Vite подставляет `VITE_*` переменные на этапе СБОРКИ (build-time), а не при запуске. Они «вшиваются» в JS-код. Если `.env` пустой — в JS попадёт fallback-значение, и API сломается
  - Как: `cat /opt/myapp/.env` → убедиться, что URL правильный → затем `npm run build`

- [ ] **Мета-теги**
  - Зачем: `<title>` и `<meta description>` — что видит пользователь в поисковой выдаче и при шаринге ссылки. `og:title/og:description` — как ссылка выглядит в Telegram/WhatsApp/VK
  - Как: в `index.html` в `<head>`

- [ ] **`<html lang="ru">`**
  - Зачем: подсказывает браузеру язык страницы. Влияет на автоперевод, голосовое чтение, и SEO для русскоязычной аудитории

## 5. Доступность из России

**Принцип:** российские провайдеры используют DPI (Deep Packet Inspection) — оборудование, которое «читает» имя домена в TLS-запросе (поле SNI). Если домен совпадает с фильтром, соединение блокируется. Это не целевая блокировка — побочный эффект массовой фильтрации.

- [ ] **www как канонический домен**
  - Зачем: голые домены чаще попадают под DPI-фильтрацию. Поддомен `www` проходит свободнее. Это подтверждённый паттерн (рекомендация поддержки reg.ru)

- [ ] **Никаких заблокированных внешних ресурсов**
  - Cloudflare — заблокирован (ECH-расширение)
  - Google CDN — может быть медленным
  - Правило: если ресурс не на твоём сервере — он может стать недоступным

- [ ] **Проверка с мобильного без Wi-Fi**
  - Зачем: мобильные операторы (МТС, Билайн, Мегафон) используют свои DPI-фильтры, отличные от домашних провайдеров. Если работает через Wi-Fi, но не через мобильный интернет — проблема в DPI

- [ ] **Российский CDN (при необходимости)**
  - Когда: если www не помогает, или нужна защита от DDoS
  - Варианты: DDoS-Guard (от $25/мес), EdgeCenter (от 500 руб/мес), Selectel CDN
  - Как работает: пользователь → CDN-сервер в Москве → твой VPS. CDN не блокируется, т.к. через него работают тысячи сайтов

## 6. Деплой и проверка

**Принцип:** каждый деплой — потенциальная точка отказа. Чеклист проверки после деплоя защищает от «всё работало, я обновил, и сайт упал».

### Порядок деплоя
```bash
cd /opt/myapp
git pull                          # 1. Получить код
npm install                       # 2. Обновить зависимости (если менялись)
cat .env                          # 3. ПРОВЕРИТЬ .env (обязательно!)
npm run build                     # 4. Собрать
# Если менялся nginx конфиг:
cp deploy/nginx.conf /etc/nginx/sites-available/domain
nginx -t && systemctl reload nginx  # 5. Проверить синтаксис → применить
```

### Проверка после деплоя
```bash
curl -I http://domain.ru           # → 301 (HTTP → HTTPS+www)
curl -I https://domain.ru          # → 301 (голый → www)
curl -I https://www.domain.ru      # → 200 (основной)
```

- [ ] Все три curl дают ожидаемые коды
- [ ] Сайт открывается в инкогнито (нет кеша)
- [ ] Сайт открывается с мобильного из РФ
- [ ] API работает (формы отправляются, данные загружаются)
- [ ] Nginx конфиг хранится в git (`deploy/`) — не только на VPS
